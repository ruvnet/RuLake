# 01 — witness-verifier-browser (Rust → wasm32-unknown-unknown)

Pure-Rust SHAKE-256 witness verification compiled to WebAssembly via
`wasm-pack build --target web`, paired with a self-contained HTML demo.

The whole pipeline runs in the browser tab — drop a real
`table.rulake.json` produced by a Rust ruLake server and the page tells
you whether the on-disk witness matches the recomputed one. No backend
round-trip. The witness is the cryptographic anchor that makes
client-side trust possible.

## What it proves

A browser can verify ruLake bundle integrity end-to-end with zero
backend involvement, against bundles produced by Rust ruLake. The wasm
verifier is a byte-exact mirror of `src/bundle.rs::compute_witness` in
the host crate — the canonical fixture in `fixtures/known-good-bundle.json`
was generated by `cargo run --release --example sidecar_daemon`.

## Build

Prereqs:

- Rust 1.85+ (`rustup`)
- `rustup target add wasm32-unknown-unknown`
- `cargo install wasm-pack`
- (optional) `wasm-opt` / `binaryen` for the size-shrink pass

```bash
./build.sh
```

`build.sh` runs `wasm-pack build --target web --release --features small`
and, if `wasm-opt` is on PATH, follows up with `wasm-opt -Oz` for the
smallest possible binary. Output:

```
pkg/
├── package.json
├── rulake_witness_verifier_browser.js          # ES-module glue
├── rulake_witness_verifier_browser_bg.wasm     # the wasm itself
├── rulake_witness_verifier_browser.d.ts
└── ...
```

## Run

Any static HTTP server. The simplest:

```bash
python3 -m http.server 8000
```

Then open <http://localhost:8000/index.html>.

The page works fully offline. There are no CDN dependencies; the
wasm-pack output is loaded as a local ES module.

## Try it

1. Click **Try sample bundle** — should render PASS in green and show
   the recomputed witness equal to the stored one.
2. Click **Tamper sample (should FAIL)** — flips `dim: 8` → `dim: 16`
   on the way in; the verifier recomputes a different witness, banner
   goes red.
3. Generate a real sidecar yourself and drag-drop it:

   ```bash
   cd /home/ruvultra/projects/RuLake
   cargo run --release --example sidecar_daemon
   # the sidecar lives in /tmp/rulake-sidecar-demo-<pid>/table.rulake.json
   ```

   Drop the file onto the drop zone. PASS in green.

## Witness algorithm

```
SHAKE-256(32) of:
    "rulake-bundle-witness-v1|"
    || u64_le(len(data_ref)) || data_ref
    || "|"
    || u64_le(dim) || u64_le(rotation_seed) || u64_le(rerank_factor)
    || "|"
    || u64_le(len(generation_bytes)) || generation_bytes
```

`generation_bytes`:

- `Num(n)`: `0x00 || u64_le(n)` — 9 bytes
- `Opaque(s)`: `0x01 || utf8_bytes(s)` — 1 + len(s) bytes

The `0x00` / `0x01` tag byte is from the 2026-04-23 audit and prevents
`Num(7)` colliding with `Opaque("\x07\0\0\0\0\0\0\0")`. `memory_class`
is intentionally NOT part of the digest — re-tagging the same vectors
with a new memory class stays cache-coherent.

## DoS caps (mirrors host crate)

- bundle JSON ≤ 64 KiB
- per-field strings (`data_ref`, `pii_policy`, `lineage_id`,
  `memory_class`) ≤ 4 KiB
- `rvf_witness` ≤ 128 chars (legitimate value is exactly 64 hex chars)

Over-cap input is rejected before any allocation-heavy work.

## Public API (wasm)

```rust
#[wasm_bindgen]
pub fn verify_bundle_json(json: &str) -> Result<JsValue, JsValue>;
//   throws on parse / cap violation; otherwise returns:
//   { ok: bool, computed: hex, stored: hex,
//     fields: { format_version, data_ref, dim, rotation_seed,
//               rerank_factor, generation, pii_policy,
//               lineage_id, memory_class },
//     error: string|null }

#[wasm_bindgen]
pub fn compute_witness_for_fields(
    data_ref: &str, dim: u64, rotation_seed: u64,
    rerank_factor: u64, generation_json: &str,
) -> Result<String, JsValue>;
```

## Binary size

`opt-level=s`, `lto=true`, `panic=abort`, default allocator, then
optional `wasm-opt -Oz`. Expected: ~80–130 KB uncompressed,
~40–55 KB gzipped. The `build.sh` script prints `ls -lh` of the final
`.wasm` so you can record the actual size for your toolchain.

(`wee_alloc` was deliberately not used — it is unmaintained and fails
to link against recent wasm-bindgen.)
